# 密钥限流、调度与请求消费

v2.4.0 在现有单容器内增加每密钥请求限流、已完成请求明细与官方 SDK 兼容回归。已有密钥默认保持不限制，累计用量账本继续保留。

## 设置请求限制

进入“密钥管理”，点击该行“设置限流”，填写并保存。

| 设置 | 取值 | 含义 |
|---|---|---|
| 每分钟请求数 | 0–60000 | 按密钥的滚动 60 秒准入次数；0 不限 |
| 同时进行的请求数 | 0–256 | 该密钥的生成请求并发上限；0 不限 |
| 并发满时最多等待 | 0–30 秒 | 0 直接返回限流提示；正数要求已设置并发上限 |

四协议共用此密钥的额度，不因切换协议或模型而重置。频率是请求数，不是 token 数或成功次数：通过鉴权、获准进入生成处理的请求占一次，之后参数校验失败也不退还频率名额。内部重试不再次占名额；鉴权和限流拒绝不占名额。模型发现等非生成接口不在这个配额中。

使用一秒桶保守记数，在 60–61 秒后释放频率额度，避免整分钟边界的双倍突发。达到上限返回 HTTP 429，并提供 `Retry-After` 及适用的 `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-Concurrency-Limit`；错误结构遵循调用协议。

排队最多每密钥 32 个、全站 512 个。等待期间重新核验停用、删除、到期、模型权限和最新策略。客户端取消后释放排队位置；完成、失败、取消后释放并发。已经开始的请求继续完成，修改限制不会强行中止它们。

列表占用是最近一次刷新的快照；读取失败显示“占用待刷新”，不会伪造为零。配置与实时计数独立保存，修改备注或开关不会覆盖消费和限流计数。全部设为 0 提交 `limits: null`；管理 API 省略 `limits` 保留原值。示例策略：

```json
{
  "limits": {
    "requests_per_minute": 60,
    "max_concurrent": 2,
    "queue_timeout_seconds": 5
  }
}
```

## 核对一条请求

进入“请求明细”，或在密钥行点击“请求明细”。按密钥管理 ID、完整模型名、状态、响应中的 `X-Request-ID` 筛选，再点击一行展开详情。管理 ID 与完整调用密钥不同；模型名保留 `cn:` / `global:` 前缀。

最终状态区分成功、失败、取消、拒绝，HTTP 200 后的流失败仍显示失败。详情列出每次实际发送给上游的请求、账号、耗时、错误与已知消费。上游已成功结束但客户端最后一帧写出失败时，上游尝试和整个客户端请求可以具有不同状态。

| 数值/状态 | 解释 |
|---|---|
| `0` | 上游明确报告为零 |
| 未知 | 上游未报告此项，不能断言免费或没有消费 |
| 部分用量 | 存在缺失的尝试或计量；数值仅为已知部分 |
| 未调用上游 | 鉴权后被本地校验或限流拒绝等，没有上游消费观测 |
| 缓存 / 推理 | 分别是输入 / 输出的子集，不重复相加 |
| 积分 | 上游报告的 credit，不从 token 数猜算价格 |

失败、取消和重试已报告的消费都会保留。结束原因区分正常停止、输出达到长度上限、工具调用与过滤。旧版本未保存的明细无法恢复，也不通过固定倍率补齐未知消费。

“本次调度”展示实际选号时的事实：会话绑定、绑定不可用、按权重选择、成本探测或冷却兜底。详情提供当时的候选/排除计数和账号。历史每千 token 积分只是调度成本观测，不是本次消费；未知成本与明确免费分开。普通筛选和兜底检查是两次扫描，排除计数不能相加当成唯一账号数。

## 留存与权限

明细只记录通过鉴权进入相关处理的已完成请求；鉴权前被拒绝的访问和尚未结束的流不在列表中。明细不保存请求/响应正文、请求头或完整调用密钥。

- 默认保留 7 天，最多 10000 条或 64 MiB；清理时可能批量腾出约 10% 的空间。
- 每条最多保存 64 次上游尝试和 64 条调度记录，超出时明确标记截断及未知覆盖。
- “用量统计”是独立累计账本，与有限留存明细的合计可能不同；密钥页账本不可读显示“—”。
- `/requests`、`/requests/{id}` 和 `/key-limits` 仅供私有管理通道；普通 API key 无权读取。面板经管理员会话转发 `/admin/api/...`。
- 尾记录恢复及明细写入失败会提示，可能不完整的列表不能解释为所有消费。

限流窗口/租约默认位于密钥库同目录 `key-limits/`，明细位于用量文件同目录 `requests.jsonl`。正常同机热重载共享状态，不重置频率或并发；退出进程的租约通过进程锁回收。限流状态损坏或锁不可用时受控请求返回 503，避免按“不限制”放行；明细故障独立报告。共享目录设计面向当前单站点，不提供多机分布式配额。
